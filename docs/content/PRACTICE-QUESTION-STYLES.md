Companion: CONTENT-HANDOFF.md (variable assessment pool). Read question-pool/73–94 and subsequent files; missing-content/54–57 contains matching, ordering, text inputs, multi-select and true/false. Preserve existing lessons and progress.

## Visual and interaction system
Use the existing Rateel visual language, landscape phone 844×390 pt (reference raster approximately 1844×853), Arabic RTL, emerald background, restrained girih, cream Arabic UI text, thin gold glass rims, existing progress/pause/replay/feedback components. Reuse actual theme tokens and fonts; Readex Pro for UI if currently configured, approved Quran font for Uthmani text. No new unrelated style, no rasterized Arabic, no new decoration that competes with the verse. Quran text is immutable and separately rendered; do not reverse character order manually or make letters morph within canonical scripture. Morphing is for separate pedagogical glyphs only. Keep prompt at top, primary stimulus centered, answer area reachable, bottom verification/continue controls; adapt for short landscape height and accessibility. Neutral target indication before answer (not a Tajwid color that gives away the answer). Feedback uses existing correct/incorrect styles, icon plus text, no color-only distinction.

## Practice state / behavior
ready -> answering -> submitted -> feedback -> continue. Allow changing selections before submit. Once submitted, freeze answer; in practice provide a concise Arabic explanation and replay, then continue or retry a targeted variant. In graded tests keep the frozen attempt question list, defer explanation to review if it would leak answers, and follow existing pass threshold. Progress increments once per completed item; do not double count retries. Provide an accessible text label for every icon and highlight. Handle long verses with wrapping or controlled scrolling, never crop words or split combining marks. Maintain RTL semantics and correct reading order; test Arabic shaping and target boundaries. Audio controls expose play/pause/replay and loading/error. If required media unavailable, replace item from approved pool or block the activity before starting; do not score it wrong.

## Data adapter / acceptance
Do not force all legacy JSON into a single schema immediately. Build a typed adapter in consolidation, normalize stable question/option/example/target IDs, map provisional topic IDs to final course/unit IDs, keep source provenance and review status. Store actual canonical text and approved span selectors using grapheme/word indices anchored to versioned verse edition; examples currently in imlai are candidates, not canonical. Reject missing/ambiguous spans, broken media, invalid keys and duplicate IDs. Strip explanatory focus before response if it reveals the answer. Preserve distinct variant families and sample across objectives and difficulty without replacement; shuffle choice presentation, never answer key IDs. Tests must cover scoring per format, RTL, retries, save/resume, media failure, unavailable variants, tap hit testing, screen reader and landscape overflow. Existing Flutter support beyond the basic question types has not been verified here; implement new renderer(s) only after inspecting current source. No changes to master in editorial branch.
