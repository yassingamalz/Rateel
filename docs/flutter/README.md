# Rateel native app (Flutter): workflow

Rebuild of the Rateel app in Flutter, replicating the **glassy gamified** design line one to one
(references: `docs/design/glassy-gamified/` on branch `lesson-production`).

## Owner's decisions (2026-11-20)
- **One screen at a time.** Each screen is built, tested and approved by the owner (look, animation,
  UX) before the next one starts.
- **One branch per screen**: `flutter/<screen-number>-<slug>` (e.g. `flutter/03-courses`), one pull
  request per screen into `master` after the owner's approval.
- **First screen: 03, courses / learning paths** (المسارات التعليمية).
- **Dark theme first.** The light/dark toggle must exist from the start; light mode is enabled later,
  when the owner decides.
- **Landscape** is the main orientation (phone and tablet).
- **Sophisticated, premium result** is the priority.
- Any missing graphic element is generated by the owner with ChatGPT / Google Flow. We write the
  prompts; we never draw art in code.

Decision log: `DECISIONS.md` (every decision is written there, in the same commit as the work).

## Per-screen process
1. **Plan**: `docs/flutter/screens/<nn>-<slug>.md` lists layout, components, motion/UX, and which parts
   are code and which are image assets. Prompts for missing assets go in
   `docs/flutter/prompts/<nn>-<slug>/images.txt` (one prompt per line, blank line between).
2. **Owner confirms** the plan and supplies the assets.
3. **Build** in `app_flutter/`, compare screenshots with the reference at the same size, iterate.
4. **Owner tests** on the device (APK / web preview) and approves → pull request into `master`.

## Asset rules (from `docs/production/RULES-AND-LESSONS-LEARNED.md`, section 6)
- One subject per image, large in the frame, high resolution. Never crop from a sheet.
- Flat magenta `#FF00FF` background, keyed out with `scripts/assets/key-magenta.py`.
- Glows, rays and sparkles on **black**, composited with a screen blend.
