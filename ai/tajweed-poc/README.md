## 1. الموديل بيشتغل إزاي؟

```
 صوت القارئ (16kHz)
      │
      ▼
 Mel filterbank  ──►  Wav2Vec2-BERT encoder (حوالي 600M باراميتر)
                              │
          ┌───────────────────┼───────────────────┐
          ▼                   ▼                   ▼
   رأس الحروف (phonemes)  رأس الغنة   ...   رأس التفخيم والترقيق      ← 11 رأس (CTC)
          │                   │                   │
          └──────── اللي القارئ قاله فعلًا ────────┘
                              │
                     مقارنة (alignment)
                              │
 نص الآية بالعثماني ──► quran_phonetizer ──► الرسم الصوتي المرجعي (اللي المفروض يتقال)
                              │
                              ▼
            أخطاء: حرف / حركة / تجويد (زمن مد، غنة...) / صفة
```

### الفكرة الأساسية: "الرسم الصوتي للقرآن"

مكتبة `quran_transcript` بتحوّل نص الآية لسلسلة أصوات **التجويد مكتوب فيها صراحةً**:

| النطق | في الرسم الصوتي |
|---|---|
| مد ٦ حركات في «الٓمٓ» | `ءَلِفلَاااااا…` يعني ٦ ألفات |
| نون مشددة بغنة في «إنّ» | `ءِننننَ` يعني النون متكررة بزمن الغنة |
| إخفاء الميم | رمز خاص `۾` |
| مد طبيعي | حرفين: `اا` أو `ۥۥ` أو `ۦۦ` |

فلما القارئ يقصّر المد اللازم لحركتين، الموديل يطلّع `اا` بدل `اااااا`، والمقارنة تطلّع:

> خطأ تجويد في «الٓمٓ»: الزمن المتوقع ٦ حركات والمنطوق ٢ ← الحكم: المد اللازم

يعني **الأزمنة والغنن والمدود بتتحول لمشكلة "عدّ حروف"**، والموديل متعلّم يكتب اللي بيسمعه بالظبط.

### الصفات

جنب رأس الحروف فيه **10 رؤوس تانية** واحدة لكل صفة: الهمس والجهر، والشدة والرخاوة، والتفخيم والترقيق، والإطباق، والصفير، والقلقلة، والتكرار، والتفشي، والاستطالة، والغنة. كل رأس بيقول لكل حرف اتنطق إيه صفته في الصوت ده، ومعاها نسبة ثقة. بعدها بنقارن بالصفة الصحيحة من المرجع.

### المعمارية

**Multi-level CTC** (`modeling/modeling_multi_level_ctc.py`): encoder واحد ومعاه `nn.Linear` لكل مستوى، والـ loss هو مجموع CTC loss لكل المستويات. الموديل اتدرّب على حوالي 850 ساعة من 22 قارئ متقن.

بيطبع الأخطاء بالعربي، وبيقيس زمن التحليل، وده مهم عشان نقرر هنشغّل على سيرفر ولا على الموبايل.

**خطة اختبار مقترحة (حوالي 15 دقيقة):**

| # | التسجيل | المتوقع |
|---|---|---|
| 1 | قارئ متقن (مثلًا الحصري من everyayah.com) يقرأ الفاتحة آية 2 | مفيش أخطاء، أو تقريبًا مفيش |
| 2 | إنت تقرأ نفس الآية صح | مفيش أخطاء، أو تقريبًا مفيش |
| 3 | تقصّر مد «ٱلْعَـٰلَمِينَ» العارض لحركتين وإنت قافل على `--madd-aared 4` | خطأ تجويد: المد العارض للسكون |
| 4 | الإخلاص آية 1 من غير قلقلة الدال في «أَحَدٌ» | خطأ صفة: القلقلة، أو خطأ تجويد |
| 5 | تفخّم حرف مرقق، أو العكس | خطأ صفة: التفخيم والترقيق |
| 6 | تبدّل حرف، زي «ض» بـ «د» | خطأ في الحرف |

ملاحظات:
- سجّل **آية واحدة أو مقطع لحد الوقف**، أقل من حوالي 15 ثانية، ومن غير استعاذة ولا بسملة قبلها.
- عدّل `--madd-monfasel` و`--madd-mottasel` و`--madd-aared` على حسب الطريقة اللي بتقرأ بيها، وإلا هيعتبر اختيارك الصحيح غلط.
- `--min-sifa-prob` بيقلّل الإنذارات الكاذبة في الصفات. ابدأ بـ 0.7 وغيّره حسب ما تشوف.

### الطريقة (ج): الـ API الجاهز، وده اللي التطبيق هيكلّمه
```bash
pip install "quran-muaalem[engine]"
# على GPU:
quran-muaalem-engine &          # الموديل، على منفذ 8000
quran-muaalem-app &             # منطق التصحيح، على منفذ 8001
# من غير GPU:
ACCELERATOR=cpu DTYPE=float32 quran-muaalem-engine &

curl -X POST http://localhost:8001/correct-recitation \
  -F "file=@recording.wav" -F "madd_monfasel_len=4"
```
الـ API **بيتعرّف لوحده على الآية** من الصوت، وبيرجّع JSON فيه مكان كل خطأ في النص العثماني (`uthmani_pos`) ونوعه والحكم بالعربي. التوثيق التفاعلي على `http://localhost:8001/docs`.

ملحوظة: الـ API بيستخدم رأس الحروف بس، يعني بيكشف أخطاء الحروف والحركات والمدود والغنة كأزمنة. لو عايز أخطاء **الصفات** لازم تستخدم مكتبة Python زي `try_muaalem.py`.

## 3. نوصّله للناس على الموبايل إزاي؟

### المرحلة 1: سيرفر (أبسط حاجة وتشتغل على طول) ✅ دي اللي ننصح بيها

```
رتّل (Capacitor)                       سيرفر GPU
───────────────                        ──────────────────────────
VoiceRecorder يسجّل آية/وقف  ──HTTPS──►  /correct-recitation
   (aac/m4a على الموبايل،               (engine + app بتوع Muaalem)
    webm على الويب)          ◄──JSON───  الأخطاء + مكانها في الآية
تلوين الكلمات الغلط على الآية
(نفس فكرة Tajweed Highlighting الموجودة)
```

- رتّل عنده تسجيل جاهز: `PlatformService.stopRecording()` بترجّع base64. نبعته `multipart/form-data` للسيرفر.
- السيرفر بيستخدم librosa/ffmpeg فبيقرا m4a وwebm. لازم نتأكد من ده في أول تجربة.
- **الحد 15 ثانية لكل طلب**، فالتطبيق يسجّل وقف بوقف، وده أصلًا مناسب لطريقة التعليم.
- السيرفر: GPU صغير زي T4 أو L4 بيكفي في البداية، والـ engine بيجمّع الطلبات مع بعض (batching) لوحده. لازم نقيس الزمن الفعلي باستخدام الطريقة (ب).
- **الخصوصية:** ناخد موافقة المستخدم قبل ما نرفع صوته، وما نخزّنش التسجيلات من غير إذن.

### المرحلة 2: تجربة تشغيل على الجهاز (offline)

`export_onnx.py` بيصدّر الموديل لـ ONNX ويضغطه لـ int8، وبيقارن الناتج بـ PyTorch:
```bash
python export_onnx.py --out onnx_model --test-audio recording.wav
```
الأرقام المتوقعة (لسه محتاجة قياس): fp32 حوالي 2.4GB، وint8 حوالي 0.6 لـ 0.7GB. ده **كبير على التطبيق** وما ينفعش يتحط جوه الـ APK، بس ممكن يتنزّل اختياري بعد التسطيب. وكمان على الموبايل محتاجين:
- نحسب الـ Mel features بنفسنا: نفس `SeamlessM4TFeatureExtractor`، اللي هو 80 mel وstride 2.
- plugin لـ Capacitor بيشغّل `onnxruntime-mobile` على Android وiOS.
- منطق المقارنة: `quran_phonetizer` و`explain_error` مكتوبين Python. الأسهل إننا **نحسب الرسم الصوتي المرجعي لكل الآيات مسبقًا** ونخزّنه JSON، وننقل المقارنة نفسها (Levenshtein على مجموعات الحروف) لـ TypeScript.

### المرحلة 3: موديل صغير مخصوص للموبايل

- **Distillation:** نستخدم Muaalem كـ "مدرّس" وندرّب موديل صغير، حوالي 30 لـ 100M زي Conformer صغير، على داتا Muaalem المفتوحة (`obadx/muaalem-annotated-v3`). المتوقع حجم 30 لـ 100MB، وده مناسب يتحط جوه التطبيق.
- أصحاب المشروع نفسهم بيشتغلوا على ده: قاسوا نسخ wav2vec2 وconformer وwhisper-encoder على LiteRT على موبايل قديم. شوف [roadmap issue #46](https://github.com/obadx/quran-muaalem/issues/46) قبل ما نبدأ من الصفر.

- **الدقة مش 100%:** الـ Tajweed F1 حسب الورقة حوالي 76%. نعرض الأخطاء اللي ثقتها عالية بس، ونقول "راجع مع شيخك" مش "إنت غلطت".
